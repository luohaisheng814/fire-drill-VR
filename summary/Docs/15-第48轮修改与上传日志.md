# 第 48 轮修改与上传日志

## 1. 本轮需求与做法

需求（用户原话要点）：

1. 操作流程训练页面点开后分成两种情形：
   - **情形 1：火势初起，烟雾开始蔓延。**
     - A（普通员工）：按动墙上火警报警按钮后，迅速向安全出口撤离，到达空旷场所。
     - B（火灾初期应对责任人）：寻找灭火器灭火，灭火后撤到安全地带。
   - **情形 2：火势已经起来，烟雾弥漫，无法灭火。**
     - A、B 都先按动火灾警报，再按规范逃生路线撤到空旷安全地带。
2. 火警警报按钮要**装在墙壁上**，按动后才开始火灾警报响应。
3. 结合**韩国官方消防安全知识**，重新设计合理的逃生路线、灭火知识与注意事项。
4. 安全出口门做**条件判断**：
   - 情形 1：门前没有火焰，右击即可开门逃出；
   - 情形 2：门前有初期火焰，必须先灭掉才能出门。
5. 以玩家视角测试，通过后提交并推送到 GitHub，并生成本日志。

做法：

- 在开始界面把原来的单个「操作流程训练」入口改为**两个情形入口**，玩家先选火情再进入演练。
- 两种情形共用同一套场景与身份系统，但流程判定按「情形 × 身份」分叉；身份仍沿用第 46/47 轮的 A/B 分配与事前教学。
- 报警按钮从落地立柱改为**贴墙壁挂**，挂在南墙 `(2.55, 0.00, -3.98)`、面向大厅；按动后由 `AlarmCallButton.onPressed → DrillScenario.OnAlarmPressed()` 驱动后续阶段。
- 情形 1 不再强制先断电、也不再要求扑灭主火；情形 2 从报警开始就把主火锁为「不可灭」，只允许处理出口门前的初期火。
- 知识墙按韩国소방청（消防厅）与국민재난안전포털（国民灾难安全门户）的公开口径重写，三语同步。

## 2. 落地细节

### 2.1 `DrillScenario`（情形与身份分叉）

新增：

- `public enum OperationCase { Incipient = 0, Developed = 1 }`：情形 1 初起 / 情形 2 已发展。
- 字段 `operationCase`、`alarmButton`；只读属性 `AlarmPressed`、`Stage1AttackForbidden`。
- `StartFormalWithCase(OperationCase, int forceSpawn = -1, int forceScenario = -1)`：按情形入口启动正式演练。
- `OnAlarmPressed()`：接收壁挂按钮事件。
- `BeginAlarmEvacuation()`：报警后直接进入疏散阶段。

关键判定：

- `StartFormal` 内按「情形 × 身份」设置：

  ```csharp
  Stage1AttackForbidden = (operationCase == OperationCase.Developed) || !RoleAllowsAttack;
  ```

  - 情形 2：任何人都不允许尝试灭主火；
  - 情形 1：普通员工不允许灭主火，负责人允许；
- 同时把 `DrillFlowDirector.unlockOnEvacuate`、`unlockOnExtinguished` 置为 `false`，避免旧流程在「疏散开始 / 主火被灭」时自动开门，门改由本轮条件逻辑控制。
- `stageTwo.exitFirePresent = (operationCase == OperationCase.Developed)`：只有情形 2 出口门前有火。
- 第 1 阶段点火锁定条件改为 `Stage1AttackForbidden || requirePowerCutBeforeExtinguish`。
- `OnAlarmPressed()` 行为：
  - 情形 1 + 负责人：只提示「继续按负责人流程灭初期火，灭完再撤」；
  - 其余组合（情形 2 的 A/B、情形 1 的 A）：立即 `BeginAlarmEvacuation()`。
- `BeginAlarmEvacuation()`：切到 `Phase.Stage2`，锁死主火，调用 `stageTwo.BeginAfterAlarm()`。
- `OnPowerCut` / `OnDeviceFireBlocked` / `OnDeviceFireExtinguished` 都加了 `Stage1AttackForbidden` 分支：给出「本情形不允许灭主火」的提示并拦截。
- `OnDeviceFireExtinguished` 在进入第 2 阶段前设 `stageTwo.exitFirePresent = false`，保证情形 1 灭完火后门前无火。

### 2.2 `AlarmCallButton`（壁挂按钮事件）

- 新增 `public UnityEngine.Events.UnityEvent onPressed`。
- `PressByScript()` 在按钮变绿后 `Invoke()`，让场景装配时挂的监听真正生效，同时保留探针直接调用入口。

### 2.3 `StageTwoFlow`（报警后疏散 + 出口门条件）

新增：

- `public bool exitFirePresent = true`：出口门前是否有火。
- `BeginAfterAlarm()`：报警后不要求灭主火，直接进入疏散。
- `OpenExitWithoutFire()`：**只解锁、不自动开门**，并且不调用 `stageTwoFire.Extinguish()`（否则会触发 `onExtinguished → Unlock()` 自动开门，玩家还没右击门就开了）。
- `EnterStageThree` 在 `!exitFirePresent` 时走 `OpenExitWithoutFire()`。
- `OnStageTwoFireExtinguished()` 开头加 `if (CurrentStage != Stage.StageThree) return;`，防止第 1 阶段的灭火事件提前把门打开。
- `TryEnterExit()` 增加 `!exitDoor.IsOpen` 拦截：门解锁了但还没开，不能直接穿门。
- `OnExitDoorEntered` 区分提示：「门还没解锁（先处理门前火情/按流程疏散）」与「门已解锁但还关着（右击开门）」。
- `Begin` / `skipEvacuation` 文案按有无门火分叉：有火提示「先灭门前初期火」，无火提示「直接右击开门撤离」。

### 2.4 `ExitDoor`（静默解锁）

- 新增 `UnlockSilently()`：只解锁、指示牌变绿，门保持关闭，等玩家右击。
- 与 `Unlock()` 区分：后者仍用于需要自动开门的旧路径。

### 2.7 `PlazaKnowledgeBoard`（韩国官方口径三语知识墙）

第三块「火灾时怎么做」：

1. 先提醒周围人；
2. 判断最近安全出口，走楼梯、不乘电梯；
3. 低姿快速撤离，不折返取物；
4. 撤到安全地带后再拨 119；
5. 到集合点清点人数；
6. 初期小火且受过训练才用灭火器。

第二块「灭火器四步」改为：

1. 拔销；
2. 握管、喷嘴对准火焰根部；
3. 压把；
4. 由近到远、由上到下扫射。

并注明：背风站位、背后留退路、只灭初期小火，火大立即撤离并拨 119。

韩文用「안전핀 뽑기 / 노즐 잡고 불꽃 밑동 / 손잡이 움켜쥐기 / 분말 골고루」，英文同步。

## 7. 韩国官方知识口径与注意事项

本轮知识墙与流程文案依据：

- 소방청「불나면 대피 먼저」五步：① 주변 사람에게 알린다 ② 대피방향을 결정한다 ③ 신속히 대피한다（엘리베이터 금지, 계단 이용）④ 119 신고（안전하게 대피한 후）⑤ 대피 후 인원 확인。
- 소화기 사용四步：안전핀 뽑기 / 노즐 잡고 불꽃 밑동 / 손잡이 움켜쥐기 / 분말 골고루（바람을 등지고, 문을 등지고, 위에서 아래로）。
- 문 손잡이가 뜨거우면 문을 열지 말고 다른 경로로 대피。

对应到本项目：

- 报警按钮装在墙上、按动即响，符合「先报警、再疏散」。
- 情形 1 普通员工：报警后不尝试灭火，直接走安全出口 → 空旷集合点。
- 情形 1 负责人：只在「初期小火 + 器材合适 + 视野清楚 + 退路安全」时灭火，灭完再撤。
- 情形 2：主火不可灭，A/B 均报警后按逃生路线撤离；出口门前初期火是唯一可处理火情。
- 出口门必须右击开门，不能穿门；门未解锁 / 门还关着都会拦截并提示。
