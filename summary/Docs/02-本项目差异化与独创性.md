# 02 · 본 프로젝트의 차별점 및 독창성 확보
# 本项目（`summary` VR 消防演练）的差异化与独创性

> 对标对象：`01-先行研究调查` 中梳理的 13 个来源（学术研究 + 商业化系统 + 韩国/中国现状）。
> 结论口径：本文只主张**可被代码与运行证据验证**的差异，不主张"算法层面的全新发明"；凡属设计整合或工程实现层面的独创性，均在文中明确标注其性质与边界。
> 한국어 요약见文末「부록 A」。

---

## 1. 一句话定位

既有消防训练程序大多在两端：一端是**只练"喷"**（灭火器仿真，判"火灭了没有"），另一端是**只练"指挥/战术"**（Go Fire、ADMS、XVR，依赖多人大场景与专用硬件）。
本项目做的是中间那条常被跳过的线——**"教学 → 考核 → 规范操作 → 扑灭 → 撤离 → 成绩单"的个人全流程闭环，且同一份工程在 VR 与桌面鼠标两条输入链上都能完整跑通，并由 152 项自动化自检守住行为一致性。**

## 3. 六项可验证的差异化设计

### 3.1 双手柄锚定的世界空间 UI（Hand-anchored UI）

**差异**：既有 VR 训练程序的界面通常是"相机固定 HUD"或"场景固定面板"；本项目的三个关键面板全部以**右手手柄为坐标系原点**：

| 面板 | 锚定参数 | 效果 |
| --- | --- | --- |
| 开始界面 `StartScreen` | 手柄前向 1.0 m + 手柄上向 0.15 m | 抬手即见，不遮挡视野，不需转身找面板 |
| 倒计时面板 `DrillCountdown` | 手柄上向 0.42 m + 手柄前向 0.12 m | 抬头即见剩余时间，低头仍看得到火焰 |
| 引导页 `OnboardingScreen` | 手柄前向 1.0 m + 手柄上向 0.14 m | 与开始界面同一套空间语言，切换无位置突变 |

**为什么算差异**：VR 训练中"找不到 UI"是高频挫败点（尤其戴头显后视野收窄）。把"信息面板挂在手上"而不是"挂在相机上"，等于把 UI 变成**身体的一部分**，减少了寻找成本，也不随头部转动摇晃（仅朝向做 billboard 平滑）。

**性质**：属于交互设计层面的独创性组合，不涉及新算法。

### 3.2 顺序不可跳步的 9 步状态机（Process-scored drill）

`FireDrillManager` 把演练拆成 ①身处火场 → ②警报 → ③确认火点 → ④移动到灭火器 → ⑤拿起 → ⑥拔销 → ⑦压把 → ⑧喷射 → ⑨扑灭，`enforceOrder = true` 时任何"跳步上报"都会被拒绝。

**差异点**：文献中最常见的评价是"火灭了没有"（2.7 提到的准确率）或"选择灭火器是否正确"，**几乎不评价"是否按安全规程的顺序操作"**。而现实事故中，"没拔销就压把""没对准就压把"恰恰是典型错误。本项目把这类错误变成**不可推进的状态**，并给出对应提示语（`StepHints`）。

**证据**：`FireSafetySelfTest` 中 `TestStepChain` 与 `TestDesktopMouseFlow` 均断言跳步被拒、按序可过。

### 3.3 限时问答作为"操作许可"（Knowledge-gated manipulation）

`ExtinguisherQuizPanel`：5 题、ABC 三选项、每题 10 秒、超时判错、通过率 0.6（3/5）。
未通过时 `Extinguisher.CanPullPin == false` → `SafetyPin` 拉不动、`PullPin()` 被拒、`TryStartSpray()` 被拒。

**差异点**：既有程序把"讲知识"与"练操作"分成两段（先看视频/听讲，再上手），二者不联动。本项目把**知识考核做成物理动作的前置条件**——"不懂原理，手就动不了"，同时答错会给知识点讲解（`teachOnWrong`），形成"错→学→再考"的闭环。

**同时它也是"决策速度"指标**：2.7 的研究指出决策速度应与准确率同评，10 秒限时正好把"想多久"变成可测数据（`CorrectCount`、超时次数）。

### 3.4 粒子累积阈值的"喷射有效性"判定（Quantified spray efficacy）

`Extinguisher.ApplySprayToFires()` 在 `sprayRange = 3 m`、`sprayAngle = 20°` 的锥形范围内逐帧累积 `extinguishRate × dt`；`FireSource` 阈值 `extinguishThreshold = 2.5 s`，达标后 `Stop(true, StopEmittingAndClear)` 立刻清空粒子、灯光归零、音效停止，并上报 ⑨。

**差异点**：实体方案（FLAIM / LION）用真实道具与传感面板换真实感，成本高；纯 VR 原型常"一喷就灭"，缺乏"持续对准"的要求。本项目用**"必须持续对准火焰根部约 2.5 秒"**这一可调参数，把"扫射手法"变成软件可判定的量，且**火焰消失是即时可见的**（不是渐隐动画），与"灭火后弹出面板"形成确定的因果反馈。

### 3.5 两阶段空间引导（灭火 → 撤离的连续引导）

- 阶段一：警报后 `GuidanceArrows.Begin()`，6 个箭头贴地指向灭火器；
- 阶段二：阶段一完成面板点「继续往下」→ `BeginLobbyGuidance()`，箭头整体切换指向 `Lobby`，每帧重排；
- 到达判定：与 `lobbyTarget` 距离 < `lobbyArriveDistance = 0.6 m` → `StopGuidance()` + `onArrivedAtLobby` → **结束页成功弹出**。

**差异点**：既有研究里"灭火训练"与"疏散演练"通常是两个独立程序（4.x 的 Go Fire 是战术级撤离，不属于单人灭火后的即时引导）。本项目把两者串成**同一次连续体验**，受训者不需要"退出再进入"，撤离方向由箭头持续给出，避免"灭完火不知道往哪走"。

### 3.6 双输入链 + 一键装配 + 152 项自检（Reproducibility as a feature）

这是本项目最"不炫但最硬"的差异：

1. **双输入链**：同一套业务逻辑（`FireDrillManager` + `Extinguisher` + `SafetyPin`）同时服务 VR 手柄与桌面鼠标。桌面键位：右键单击灭火器=答题/拿起、左键单击=拔销、左键双击=压把、右键双击=喷射/停止、P=放下。这对应文献 4.1 中 Go Fire 为晕动症受训者提供"显示器模式"的思路，但本项目把**完整操作链**都做成了鼠标可完成，而不是只给"观看模式"。
2. **一键装配**：`FireSafety/一键搭建场景` 菜单从空场景生成 XR Origin、双控制器、移动、开始界面、警报、BGM、倒计时、箭头、阶段面板、引导页、结束页、两台灭火器（含抓取/问答/拔销/压把/粒子）、EventSystem 与桌面输入，并保存场景。
3. **自动化自检**：`FireSafetySelfTest.RunAll()` 覆盖压把逻辑、粒子配置、桌面鼠标全流程、HUD、问答逻辑与失败重试、阶段面板、大厅引导、引导页/结束页、步骤链、场景装配，共 **152 项断言**，批处理命令行可复跑，退出码即结论。

**为什么这是独创性**：在调查范围内，未见公开的 VR 消防训练工程同时具备"双输入等价链路 + 一键可复现装配 + 百级自动化断言"。这让本项目可以作为**可复现的实验平台**（改参数 → 跑一遍 → 得到同一套断言结果），而不是一次性演示。

## 4. 独创性主张的边界（诚实声明）

| 主张 | 是否成立 | 说明 |
| --- | --- | --- |
| "全球首个 VR 消防演练系统" | **不成立** | Go Fire、FLAIM、ADMS 等早已商用，本项目的场景规模远小于它们 |
| "新的火焰/烟气物理算法" | **不成立** | 本项目用粒子系统 + 累积阈值近似，不做 FDS 级流体仿真 |
| "首次把限时问答作为灭火器操作门控" | **在调查范围内未见相同实现**，但不能断言"首次" | 调查仅覆盖 13 个来源，未做系统综述（PRISMA）级别的穷举 |
| "首次实现灭火→撤离→成绩单的单人闭环" | **在调查范围内未见相同组合** | arXiv 2508.15788 含疏散环节，但未与"限时知识门控 + 顺序状态机 + 结束页成绩单"组合 |
| "工程可复现性达到研究平台水平" | **成立（可验证）** | 152 项断言 + 批处理复跑，是本文档可直接出示的证据 |

**结论表述建议**（可直接用于报告/答辩）：

> 本项目不主张在火灾仿真算法上超越既有系统，而主张在**"个人全流程闭环的操作规范性评价"与"低成本可复现部署"**两个维度上形成差异化：以 9 步顺序状态机保证流程不被跳步、以限时知识门控保证"知其所以然"、以两阶段箭头把灭火与撤离连成一次体验、以结束页把过程数据变成可读成绩，并以双输入链与 152 项自动化自检保证同一份工程在不同硬件条件下行为一致。

## 5. 尚未完成、需要补的实验（避免"只讲设计不讲验证"）

当前证据只有**功能与装配层面的自动化断言**，尚无**人因效果数据**。要真正支撑"优于既有视频培训"的主张，需要补：

| 实验 | 设计 | 指标 |
| --- | --- | --- |
| 对照实验 | 本项目 VR 组 / 桌面鼠标组 / 训练视频组，各 ≥ 20 人，随机分配 | 即时测验分数、操作步骤正确率、完成时间、错误类型分布 |
| 保持测试 | 训练后 2 周复测 | 知识保持率、操作步骤遗忘点 |
| 可用性 | NASA-TLX 负荷问卷 + 晕动症 SSQ | 主观负荷、晕动症发生率（对比 VR 与桌面组） |
| 迁移 | 真实灭火器（训练用）实操评分 | 顺序正确率、拔销到喷射的时延 |

上述实验**尚未开展**，因此本文档不给出任何效果优劣的数值结论。

## 부록 A · 한국어 요약 (Korean summary)

1. **포지셔닝**: 기존 프로그램은 "분사만 평가하는 소화기 시뮬레이터"와 "고비용 하드웨어 기반 지휘·전술 훈련"으로 양분되어 있다. 본 프로젝트는 그 사이의 **개인 전 과정 폐쇄 루프**(온보딩 → 지식평가 → 규정 순서 조작 → 소화 → 대피 → 성적표)를 저비용으로 구현한다.
2. **차별점 6가지**: ① 손잡이(컨트롤러) 기준 월드공간 UI(시작 1.0 m/0.15 m, 카운트다운 0.42 m/0.12 m, 온보딩 1.0 m/0.14 m), ② 9단계 상태머신 + `enforceOrder`(순서 건너뛰기 차단), ③ 제한시간 퀴즈를 **조작 허가 조건**으로 사용(5문항×10초, 60%), ④ 입자 누적 임계값(약 2.5초 지속 조준)으로 분사 효과 판정, ⑤ 소화→대피를 잇는 2단계 유도 화살표(0.6 m 도달 판정 → 엔딩), ⑥ **VR/데스크톱 이중 입력 + 원클릭 씬 조립 + 152개 자동 검증**.
3. **독창성의 성격**: 화재 물리 알고리즘의 신규성은 주장하지 않는다. 독창성은 **"절차 규범성 평가"와 "저비용 재현 가능성"**이라는 통합 설계에 있다.
4. **한계**: 인적 효과 실험(대조군, NASA-TLX, SSQ, 2주 유지 테스트)은 **미실시**이므로 효과 우위의 수치적 결론은 제시하지 않는다.
5. **기여**: 본 엔진은 파라미터를 바꿔 재실험할 수 있는 **연구용 플랫폼**으로 쓰일 수 있으며, 이후 사용성·학습효과 실험의 기반이 된다.
